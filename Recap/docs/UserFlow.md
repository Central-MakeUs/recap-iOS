    # RE-CAP 유저 플로우 정의서 v0.1
    
    ## 0. 문서 목적
    
    - RE-CAP MVP에서 사용자가 주요 기능을 이용할 때 거치는 화면 이동 흐름을 정의한다.
    - 이 문서는 플로우차트, 화면 목록표, 화면설계서 작성 시 기준 문서로 사용한다.
    
    ---
    
    ## 1. 작성 기준
    
    | 구분 | 기준 |
    | --- | --- |
    | 작성 범위 | MVP 핵심 기능을 이용하는 주요 사용자 흐름을 중심으로 작성한다. |
    | 작성 방식 | 플로우별로 시작 지점, 완료 지점, 화면 이동 흐름을 분리해 작성한다. |
    | 예외 처리 | 실패, 권한 거부, 네트워크 오류 등 상세 분기는 플로우차트에서 정의한다. |
    | 화면 기준 | 실제 화면 이동이 발생하는 단위를 기준으로 작성한다. |
    
    | 기준 | 내용 |
    | --- | --- |
    | 업로드 | 사용자는 앱 내 선택 업로드 또는 공유하기 업로드로 정리를 시작한다. |
    | 자동 정리 | 업로드 이후 정리 완료, 확인 필요, 실패 안내 중 하나로 처리된다. |
    | 확인 필요 | 확인 필요 캡처는 홈 배너에서 진입해 저장하거나 삭제할 수 있다. |
    | 탐색 | 정리 완료 캡처는 홈, 컬렉션, 검색에서 찾을 수 있다. |
    | 상세 | 캡처 상세에서는 원본 확인, 제목/요약/컬렉션 수정, 삭제가 가능하다. |

    ### RE-CAP 핵심 유저스토리 정의서 v0.1
    
    ## 0. 문서 목적
    
    - RE-CAP MVP에서 사용자가 반드시 수행해야 하는 핵심 행동을 사용자 목표 중심으로 정의한다.
    - 이 문서는 유저 플로우, 플로우차트, 화면 목록표, 화면설계서 작성 시 기준 문서로 사용한다.
    
    ---
    
    ## 1. 작성 기준
    
    | 구분 | 기준 |
    | --- | --- |
    | 작성 범위 | RE-CAP MVP에서 반드시 검증해야 하는 핵심 사용자 행동을 중심으로 작성한다. |
    | 작성 방식 | 사용자의 상황, 목표, 행동, 완료 기준을 기준으로 정리한다. |
    | 제외 범위 | 화면 배치, 상세 UI 문구, API 처리 방식, DB 구조는 포함하지 않는다. |
    | 연결 문서 | 서비스 정책서, 기능 동작 정책서, IA, 화면별 기능 정의서와 연결해 사용한다. |
    1. 사용자는 정리하고 싶은 이미지를 직접 선택하거나 공유할 수 있어야 한다.
    2. 사용자는 업로드 후 별도 입력 없이 자동 정리 결과를 받을 수 있어야 한다.
    3. 사용자는 정리 완료된 캡처를 홈, 컬렉션, 검색에서 다시 찾을 수 있어야 한다.
    4. 사용자는 확인 필요 캡처를 확인하고 저장하거나 삭제할 수 있어야 한다.
    5. 사용자는 AI 정리 결과를 수정하고, 필요 없는 캡처를 삭제할 수 있어야 한다.

    ## 2. 핵심 사용자
    
    | 항목 | 내용 |
    | --- | --- |
    | 주요 사용자 | 정보성 스크린샷을 자주 저장하지만, 다시 찾거나 정리하는 데 어려움을 겪는 사용자 |
    | 주요 상황 | 맛집, 상품, 일정, 예약, 채용 공고, 레퍼런스 등 나중에 다시 볼 정보를 스크린샷으로 저장함 |
    | 핵심 문제 | 저장한 스크린샷이 갤러리에 섞여 다시 찾기 어렵고, 내용을 확인하려면 이미지를 하나씩 열어봐야 함 |
    | 핵심 목표 | 다시 보고 싶은 스크린샷을 쉽게 정리하고, 필요한 순간 빠르게 찾고 싶음 |

    | US-02 | 사용자가 OS 공유 메뉴에서 RE-CAP을 선택해 이미지를 전달할 수 있다. |
    | US-03 | 업로드된 이미지는 OCR/이미지 분석을 거쳐 제목, 요약, 컬렉션 생성이 시도된다. |
    | US-04 | 정리 완료된 캡처는 목록에서 제목, 요약, 썸네일을 통해 내용을 파악할 수 있다. |
    | US-05 | 확인 필요 캡처는 홈 배너와 확인 필요 목록에서 접근할 수 있고, 상세에서 저장 또는 삭제할 수 있다. |
    | US-06 | 사용자는 기본 컬렉션 4개를 확인하고, 각 컬렉션에 속한 캡처 목록을 볼 수 있다. |
    | US-07 | 사용자는 검색어를 입력해 정리 완료된 캡처를 찾을 수 있고, 결과가 없으면 빈 상태를 확인할 수 있다. |
    | US-08 | 사용자는 캡처 상세에서 원본 이미지와 AI 정리 결과를 함께 확인할 수 있다. |
    | US-09 | 사용자는 캡처 상세에서 제목, 요약, 컬렉션을 수정하고 변경 결과를 목록에 반영할 수 있다. |
    | US-10 | 사용자는 캡처를 삭제할 수 있고, 삭제된 캡처는 홈, 컬렉션, 검색 결과에 노출되지 않는다. |
    | US-11 | 사용자는 정리 시작 전 선택 목록에서 이미지를 제거할 수 있고, 정리 후에는 캡처를 삭제할 수 있다. |
    | US-12 | 사용자는 컬렉션 상세에서 해당 컬렉션 안의 캡처만 대상으로 검색할 수 있다. |

    ## 5. MVP 핵심 시나리오
    
    - **시나리오 1. 앱 안에서 스크린샷 정리하기**
        - 사용자는 RE-CAP 홈에서 정리할 이미지를 선택한다.
        - 선택한 이미지 목록을 확인한 뒤 정리 시작을 누르면 AI가 제목, 요약, 컬렉션을 생성한다.
        - 결과가 충분하면 정리 완료 상태로 저장되고, 홈과 컬렉션에서 확인할 수 있다.
    - **시나리오 2. 공유하기로 스크린샷 보내기**
        - 사용자는 스크린샷을 찍은 직후 또는 갤러리에서 공유 메뉴를 연다.
        - RE-CAP을 선택하면 해당 이미지가 RE-CAP으로 전달된다.
        - 공유된 이미지는 정책에 따라 즉시 정리되거나 정리 전 확인 단계를 거친다.
    - **시나리오 3. 확인 필요한 캡처 처리하기**
        - AI가 제목, 요약, 컬렉션 중 하나 이상을 확정하지 못하면 해당 캡처는 확인 필요 상태로 분리된다.
        - 사용자는 홈 배너에서 확인 필요 목록으로 이동하고, 상세에서 원본과 정리 결과를 확인한다.
        - 컬렉션을 선택한 뒤 저장하면 정리 완료 상태가 되고, 필요 없는 캡처는 삭제할 수 있다.
    - **시나리오 4. 정리된 캡처 다시 찾기**
        - 사용자는 홈, 컬렉션, 검색을 통해 정리된 캡처를 찾는다.
        - 목록에서 제목과 요약을 보고 내용을 파악하고, 필요한 경우 캡처 상세로 이동해 원본 이미지를 확인한다.
    - **시나리오 5. 정리 결과 수정 또는 삭제하기**
        - 사용자는 캡처 상세에서 AI가 만든 제목, 요약, 컬렉션을 확인한다.
        - 내용이 부정확하면 직접 수정할 수 있고, 더 이상 필요 없는 캡처는 삭제할 수 있다.

        # RE-CAP 플로우차트 작성 계획 v0.1
        
        ## 0. 작성 기준
        
        RE-CAP 플로우차트는 유저 플로우에서 정의한 화면 이동 흐름을 기준으로, 각 단계의 조건 분기와 처리 결과를 시각화한다.
        
        유저 플로우가 “사용자가 어떤 화면을 거치는지”를 정리한 문서라면, 플로우차트는 “어떤 조건에서 어떤 상태로 이동하는지”를 정리하는 문서다.

        ## 1. 전체 연결 구조
        
        ```
        FC-01 앱 내 선택 업로드
                ↓
        FC-03 자동 정리 처리
                ↓
        정리 완료 / 확인 필요 / 실패 안내
        ```
        
        ```
        FC-02 공유하기 업로드
                ↓
        FC-03 자동 정리 처리
                ↓
        정리 완료 / 확인 필요 / 실패 안내
        ```
        
        ```
        정리 완료
        → FC-05 정리된 캡처 탐색
        → FC-06 캡처 상세 수정/삭제
        ```
        
        ```
        확인 필요
        → FC-04 확인 필요 캡처 처리
        → 저장 시 정리 완료
        → FC-05 정리된 캡처 탐색
        ```
        
        ```
        실패 안내
        → 다시 시도
        → FC-03 자동 정리 처리 또는 이전 단계로 복귀
        ```

        | 저장 성공 | 정리 완료 상태로 전환 |
        | 삭제 선택 | 삭제 확인 |
        | 삭제 확정 | 삭제됨 |
        | 사용자가 화면 이탈 | 확인 필요 상태 유지 |

        ## 9. 최종 작성 기준
        
        | 기준 | 내용 |
        | --- | --- |
        | FC-01, FC-02 | 업로드 진입 경로를 각각 분리해서 작성한다. |
        | FC-03 | 앱 내 업로드와 공유하기 업로드 이후 공통으로 타는 자동 정리 처리 흐름이다. |
        | FC-04 | 확인 필요 상태가 된 캡처만 처리한다. |
        | FC-05 | 정리 완료된 캡처를 다시 찾는 탐색 흐름이다. |
        | FC-06 | 캡처 상세에서 발생하는 수정, 컬렉션 변경, 삭제 흐름이다. |
        | 연결 방식 | 각 플로우차트는 독립적으로 그리되, 종료 지점과 다음 플로우차트의 시작 지점이 연결되도록 설계한다. |
