## 2. Problem Definition

- 사용자는 나중에 다시 보기 위해 스크린샷을 저장하지만, 저장된 스크린샷은 곧바로 활용 가능한 정보 상태가 아님.
- 스크린샷은 갤러리에 이미지 형태로 쌓이고, 사용자는 필요한 순간마다 다시 스크롤하고, 이미지를 열고, 확대하고, 내용을 읽어야 함.
- 이 과정이 반복되면서 저장한 정보는 실제 행동이나 참고로 이어지지 못하고 방치됨.

### 핵심 문제

> 스크린샷 저장은 쉽지만, 저장 이후 다시 찾고 이해하고 활용하는 과정이 번거로워 정보의 활용 가치가 사라짐.
> 

### Pain Point

| Pain Point | 설명 |
| --- | --- |
| 식별 비용 | 썸네일만 보고 어떤 캡처인지 알기 어려움 |
| 탐색 비용 | 원하는 스크린샷을 찾기 위해 갤러리를 계속 스크롤해야 함 |
| 확인 비용 | 이미지를 하나씩 열고 확대해야 내용을 알 수 있음 |
| 활용 단절 | 저장은 했지만 다시 보지 않거나, 찾지 못해 활용을 포기함 |

---

## 3. Product Goal

RE-CAP의 목적은 **사용자가 다시 보고 싶은 스크린샷을 보내면, 다시 찾고 활용하기 쉬운 정보카드로 정리하는 것**임.

### MVP Goal

> 사용자가 선택하거나 공유한 스크린샷이 자동으로 정보카드로 정리되고, 최신순·검색·유형·즐겨찾기로 다시 찾을 수 있는지 검증함.
> 

### 핵심 가설

| 가설 | 설명 |
| --- | --- |
| H1 | 사용자는 다시 볼 가치가 있는 스크린샷이라면 RE-CAP에 직접 보내는 행동을 감수함 |
| H2 | 스크린샷이 제목/요약/핵심 정보가 있는 카드로 바뀌면 갤러리보다 빠르게 내용을 파악할 수 있음 |
| H3 | 자동 업로드 없이도 선택 업로드/공유하기 플로우가 충분히 간단하면 반복 사용 가능함 |
| H4 | 유형·검색·즐겨찾기만으로도 초기 탐색 피로를 줄일 수 있음 |

---

## 4. Target User

### RE-CAP MVP 1차 타겟

**정보성 스크린샷을 자주 저장하고, 저장한 정보를 실제로 다시 활용해야 하는 20대 지식 작업자**

| 항목 | 정의 |
| --- | --- |
| 주요 타겟 | 대학생, 취업 준비생, 주니어 기획자/디자이너/마케터 |
| 저장 대상 | 채용 공고, 일정, 상품, 맛집, 레퍼런스, 인사이트, 업무 자료 |
| 행동 특성 | 일단 스크린샷으로 저장하지만 나중에 찾는 데 어려움을 느낌 |
| 핵심 니즈 | 저장한 정보를 다시 찾고, 빠르게 확인하고, 활용하고 싶음 |

## 5. Solution Concept

RE-CAP은 사용자가 보낸 스크린샷을 자동으로 분석해 **정보카드**로 전환함.

### As-Is

- `스크린샷 저장 → 갤러리 방치 → 필요할 때 스크롤 → 이미지 열기 → 확대/확인 → 활용 또는 포기`

### To-Be

- `스크린샷 선택/공유 → RE-CAP 전송 → OCR/AI 분석 → 정보카드 생성 → 유형/키워드 부여 → 검색/유형/즐겨찾기로 재탐색`

### 핵심 솔루션

| 기존 문제 | RE-CAP 솔루션 |
| --- | --- |
| 이미지를 열기 전까지 내용을 알 수 없음 | 제목, 요약, 핵심 정보로 먼저 파악 |
| 갤러리에서 직접 찾아야 함 | 최신순, 유형, 검색, 즐겨찾기로 탐색 |
| 직접 앨범을 만들어야 함 | AI가 유형과 키워드를 자동 부여 |
| 불필요한 사진까지 섞임 | 사용자가 보낸 스크린샷만 정리 |
| 개인정보 우려 | 자동 전체 업로드 없이 선택 기반 업로드 |

## 6. Input Strategy

| 개념 | 정의 | MVP 여부 |
| --- | --- | --- |
| 선택 업로드 | 사용자가 갤러리에서 정리할 스크린샷을 직접 선택 | P0 |
| 공유하기 전송 | 스크린샷/이미지에서 공유 버튼으로 RE-CAP에 전송 | P0 |
| 자동 정보카드 생성 | 사용자가 보낸 이미지를 제목, 요약, 유형, 키워드가 있는 카드로 생성 | P0 |
| 자동 업로드 | 새로 찍은 스크린샷을 앱이 자동으로 가져옴 | MVP 제외 |
| 무승인 자동 분석 | 사용자가 보내지 않은 이미지를 자동으로 분석 | MVP 제외 |

### Non-Goals

| 제외 항목 | 제외 이유 |
| --- | --- |
| 자동 업로드 | 개인정보, 권한, 비용, 불필요한 카드 누적 리스크 |
| 백그라운드 자동 감지 | OS 제약 및 안정성 리스크 |
| 전체 사진첩 분석 | 서비스 목적과 다르고 신뢰 부담이 큼 |
| 목적형 4컬렉션 | 사용자 저장 목적은 이미지 내용만으로 안정적으로 판단하기 어려움 |
| 확인 필요 전용 화면 | MVP에서는 예외 화면을 만들지 않고 카드 수정으로 처리 |
| 소분류 자동 부여 | MVP에서는 검색 키워드가 세부 탐색 역할을 대체 |
| 속성 필터/임박 카드 | 마감일·가격 등 구조화 데이터의 정확도 검증 이후 도입 |
| 팀 공유 기능 | 개인 생산성 경험 검증 이후 확장 |

### MVP 정책

> MVP에서는 사용자가 직접 선택하거나 공유하기로 보낸 스크린샷만 업로드하고, AI가 자동으로 정보카드로 정리함.
>

## 7. MVP Core Flow

### Flow 1. 첫 사용

- `앱 실행 → 온보딩 → 사진 접근/업로드 안내 → 스크린샷 선택 → 정리 시작 → 정보카드 생성 → 홈 진입`

### Flow 2. 공유 저장

- `스크린샷 촬영 → 공유 버튼 → RE-CAP 선택 → 업로드 → 자동 카드화 → 저장 완료`

### Flow 3. 카드 탐색

- `홈/유형/검색 → 카드 선택 → 요약 확인 → 원본 보기/수정/삭제`

### Flow 4. 카드 수정

- `카드 상세 → 수정 → 제목/요약/유형/키워드 수정 → 저장`

## 9. Information Card Structure

- 정보카드 정의
    
    > 정보카드는 원본 스크린샷을 열기 전에, 이 캡처가 무엇이고 어떤 정보가 중요한지 알 수 있게 만든 요약 단위임.
    > 
- 카드 구성
    
    
    | 카드 요소 | 우선순위 | 설명 |
    | --- | --- | --- |
    | 원본 이미지 | P0 | 사용자가 원본 스크린샷 확인 |
    | 썸네일 | P0 | 카드 목록에서 빠르게 식별 |
    | 제목 | P0 | OCR/AI 기반 자동 생성 |
    | 1줄 요약 | P0 | 이미지를 열지 않아도 핵심 내용 파악 |
    | 유형 | P0 | 9개 유형 + 기타 중 1개 |
    | 키워드 | P0 | 검색 보조용 핵심어 |
    | 핵심 정보 | P0 | 유형별로 카드에 우선 노출할 값 |
    | OCR 텍스트 | P0 | 검색/분석용 내부 데이터 |
    | 저장일/업로드일 | P0 | 최신순 정렬 기준 |
    | 즐겨찾기 | P0 | 사용자가 직접 고정 |
    | 상태 | P0 | 정리 중/완료/실패/삭제됨 |
    | 메모 | P1 | 사용자가 직접 입력 |
- 카드 상태
    
    
    | 상태 | 사용자 화면 의미 |
    | --- | --- |
    | 정리 중 | 업로드 후 제목/요약/유형/키워드를 생성하는 중 |
    | 정리 완료 | 정보카드 생성이 완료된 상태 |
    | 정리 실패 | 업로드 또는 분석 실패로 재시도가 필요한 상태 |
    | 삭제됨 | 사용자가 삭제한 상태 |
    
    > `기타`는 상태가 아니라 유형 값임.
    > 
    > 
    > 유형 판별이 어려운 경우 전용 확인 필요 화면으로 보내지 않고, `기타`로 배정한 뒤 사용자가 카드 상세에서 수정할 수 있게 함.
    >

## 11. AI Processing Policy

### 권장 처리 방식(예시)

- `이미지 업로드 → OCR → AI 분석 → 정보카드 생성 → 유형/키워드 저장 → 카드 노출`
    
    
    | 단계 | 처리 방식 |
    | --- | --- |
    | OCR | 스크린샷 내 텍스트 추출 |
    | 제목 생성 | 캡처 내용을 대표하는 제목 생성 |
    | 요약 생성 | 핵심 내용을 1줄로 요약 |
    | 유형 분류 | 9개 유형 + 기타 중 1개 배정 |
    | 키워드 추출 | 고유명사, 장소명, 상품명, 회사명 등 검색어 추출 |
    | 핵심 정보 추출 | 유형별 요약 필드에 맞는 값 추출 |
    | 실패 처리 | 분석 실패 시 정리 실패 상태 표시 및 재시도 제공 |
    | 비용 관리 | 모든 이미지를 고비용 모델에 태우지 않고 OCR/규칙 기반 처리 우선 검토 |
- 유형 판별 실패 정책
    
    
    | 상황 | 처리 |
    | --- | --- |
    | 유형 판단 불가 | 기타로 배정 |
    | 제목/요약 일부 부족 | 가능한 값으로 카드 생성 |
    | OCR 실패 | 이미지 기반 제목/요약 시도, 불가 시 정리 실패 |
    | 사용자가 결과 불만족 | 카드 상세에서 제목/요약/유형/키워드 수정 |
