## 4.  스크린샷 정리 처리 정책

- 정리 처리 상태는 업로드된 이미지가 RE-CAP에서 어떤 단계에 있는지 구분하기 위한 기준
- 사용자에게 명확히 상태로 노출되는 것은 정리 중과 확인 필요이며, 정리 완료는 일반 캡처 목록에 노출되는 것으로 상태를 대체

| 상태 | 의미 | 노출 위치 |
| --- | --- | --- |
| 정리 중 | 이미지 업로드 후 AI 분석이 진행 중인 상태 | 분석이 즉시 끝나지 않을 경우 정리 중 화면 또는 홈 내 상태로 노출 |
| 정리 완료 | 제목, 요약, 컬렉션이 생성되어 일반 캡처로 확인 가능한 상태 | 별도 상태 라벨 없이 홈, 컬렉션, 검색 결과에 노출 |
| 확인 필요 | AI 정리 결과가 불확실하거나 정보가 부족해 사용자 확인이 필요한 상태 | 홈 배너, 확인 필요 목록 |
| 삭제됨 | 사용자가 정리된 캡처를 삭제한 상태 | 홈, 컬렉션, 검색 결과에 노출하지 않음 |
| 선택 목록에서 제거됨 | 정리 시작 전 사용자가 선택 이미지 목록에서 제거한 상태 | 업로드 및 AI 분석 대상에 포함하지 않음 |

## 5. 확인 필요 스크린샷 정책

- 확인 필요한 스크린샷: 자동 정리 결과가 불확실한 캡처를 사용자가 최소 행동으로 확인·수정한 뒤 저장하거나 삭제할 수 있게 하는 예외 영역이다.

| 정책 영역 | 항목 | 정책 | 화면/기능 연결 |
| --- | --- | --- | --- |
| 확인 필요 | 목적 | 확인 필요는 자동 정리 결과가 불확실한 캡처를 사용자가 확인·수정한 뒤 저장하거나 삭제할 수 있게 하는 예외 상태다. | 확인 필요 목록, 확인 필요 상세 |
| 확인 필요 | 발생 기준 | AI가 제목, 요약, 컬렉션 중 하나 이상을 신뢰도 있게 확정하지 못하거나, 정리할 정보가 부족하다고 판단한 경우 확인 필요로 분리한다. | 정리 중 → 확인 필요 |
| 확인 필요 | 진입 방식 | 확인 필요한 캡처가 있을 때만 홈에 조건부 배너로 노출한다. | 홈 |
| 확인 필요 | 목록 | 확인 필요한 캡처를 한 화면에서 모아볼 수 있다. 목록에서는 수정하지 않고, 특정 캡처 선택 시 확인 필요 상세로 이동한다. | 확인 필요 목록 → 확인 필요 상세 |
| 확인 필요 | 상세 | 원본 이미지와 정리 결과 미리보기 항목인 제목, 요약, 컬렉션을 함께 보여준다. 
생성된 값이 없으면 비어 있는 상태 또는 안내 문구로 표시한다. | 확인 필요 상세 |
| 확인 필요 | 제목 수정 | 사용자는 자동 생성된 제목이 부정확하거나 비어 있을 경우 제목을 수정할 수 있다. 단, 제목 수정은 저장 필수 조건은 아니다. | 확인 필요 상세 |
| 확인 필요 | 요약 수정 | 사용자는 자동 생성된 요약이 부정확하거나 부족할 경우 요약을 수정할 수 있다. 단, 요약 수정은 저장 필수 조건은 아니다. | 확인 필요 상세 |
| 확인 필요 | 컬렉션 선택/변경 | 컬렉션이 없거나 분류가 불확실한 경우 사용자가 컬렉션을 선택하거나 변경할 수 있다. | 확인 필요 상세 |
| 확인 필요 | 저장 조건 | 확인 필요 캡처는 컬렉션이 선택되어 있어야 저장할 수 있다. 제목과 요약은 비어 있거나 부족해도 저장할 수 있다. | 확인 필요 상세 |
| 확인 필요 | 사용자 행동 | 사용자는 확인 필요 캡처를 수정 후 저장하거나, 필요 없는 캡처를 삭제할 수 있다. | 확인 필요 상세 |
| 확인 필요 | 저장 결과 | 저장하면 해당 캡처는 확인 필요 상태에서 정리 완료 상태로 전환되며, 이후 홈, 컬렉션, 검색 결과 및 일반 캡처 상세에서 확인할 수 있다. | 확인 필요 상세 
→ 홈/컬렉션/검색/캡처 상세 |
| 확인 필요 | 삭제 결과 | 사용자가 삭제하면 해당 캡처는 홈, 컬렉션, 검색 결과에 노출되지 않는다. | 확인 필요 상세 |

### RE-CAP 기능 동작 정책서 v0.1

## 0. 문서 목적

- RE-CAP MVP에서 제공하는 주요 기능의 **동작 기준, 처리 상태, 예외 처리 기준**을 정의한다.
- 이 문서는 유저 플로우, 플로우차트, 화면 목록표, 화면설계서 작성 시 기준 문서로 사용한다.
    1. 사용자가 직접 선택하거나 공유한 이미지만 업로드한다.
    2. 업로드된 이미지는 OCR과 이미지 분석을 통해 자동 정리한다.
    3. 정리 결과는 제목, 요약, 컬렉션으로 구성한다.
    4. 정리 결과가 충분하면 정리 완료 상태로 저장한다.
    5. 결과가 불확실하거나 정보가 부족하면 확인 필요 상태로 분리한다.
    6. 시스템 장애, 네트워크 오류, 외부 AI 장애는 확인 필요가 아니라 실패 안내와 재시도 대상으로 처리한다.
    7. 사용자는 정리 시작 전 선택 목록에서 이미지를 제거할 수 있다.
    8. 사용자는 정리 후 제목, 요약, 컬렉션을 수정하거나 캡처를 삭제할 수 있다.
    9. 자동 업로드, 개인 컬렉션 생성, 이미지 자체 검색, 자동 마스킹은 MVP에서 제외한다.

## 3. 캡처 처리 상태와 변경 기준

- 사용자가 업로드한 이미지가 RE-CAP 안에서 어떤 상태로 처리되고, 어떤 조건에서 다음 단계로 바뀌는지 정의
- 캡처 데이터에 저장되는 상태와, 화면에서만 안내되는 처리 상태를 구분해 관리한다.

### 3-1. 상태 구분 기준

| 구분 | 의미 | 항목 | 비고 |
| --- | --- | --- | --- |
| 캡처 상태 | 업로드 이후 생성된 캡처가 실제로 가질 수 있는 상태 | 정리 중, 정리 완료, 확인 필요, 삭제됨 | 주요 데이터 상태값으로 사용 |
| 화면 안내 상태 | 사용자의 진행 상황이나 오류를 화면에서 안내하기 위한 상태 | 업로드 대기, 실패 안내, 재시도 가능 | 실제 데이터 상태값으로 저장할지는 개발 `논의 필요` |
| 업로드 전 행동 | 정리 시작 전에 사용자가 선택한 이미지를 조정하는 행동 | 선택 목록에서 제거 | 캡처 데이터 생성 전이므로 상태값으로 보지 않음 |

### 3-2. 캡처 상태 정의

| 상태 | 정의 | 사용자 노출 기준 |

| 정리 완료 | 제목, 요약, 컬렉션이 생성되어 일반 캡처로 확인 가능한 상태 | 별도 상태 라벨 없이 홈, 컬렉션, 검색 결과에 노출 |
| 확인 필요 | AI 결과가 불확실하거나 정보가 부족해 사용자 확인이 필요한 상태 | 홈 배너, 확인 필요 목록에 노출 |
| 삭제됨 | 사용자가 캡처를 삭제한 상태 | 홈, 컬렉션, 검색 결과에 노출하지 않음 |

## 5. 스크린샷 자동 정리 동작 정책

- 자동 정리 결과는 제목, 요약, 컬렉션이 모두 충분히 생성된 경우에만 정리 완료로 처리한다.
- 분석은 완료됐지만 제목, 요약, 컬렉션 중 하나 이상이 부족하거나 불확실하면 확인 필요로 분리한다.
- 업로드 실패, 네트워크 오류, AI 응답 실패처럼 정리 결과 자체를 만들 수 없는 경우에는 확인 필요가 아니라 실패 안내와 재시도 대상으로 처리한다.

### 5-1. 동작 기준

| ID | 조건/트리거 | 동작 정책 | 결과 상태 | 논의 필요 |
| --- | --- | --- | --- | --- |
| AI-01 | 이미지 업로드 완료 | OCR과 이미지 분석을 활용해 이미지 내용을 파악한다. | 정리 중 | **사용할 OCR/AI 방식** |
| AI-02 | OCR 결과 또는 이미지 단서가 명확함 | 명확한 키워드나 패턴은 규칙 기반으로 우선 처리할 수 있다. | 정리 중 | **규칙 목록 정의** |
| AI-03 | 문맥 판단이 필요함 | AI 분석을 통해 제목, 1줄 요약, 컬렉션을 생성한다. | 정리 완료 또는 확인 필요 | 모델/프롬프트 기준 |
| AI-04 | 제목, 요약, 컬렉션 생성 성공 | 캡처를 정리 완료 상태로 저장한다. | 정리 완료 | **정리 완료 최소 기준** |
| AI-05 | 결과가 불확실하거나 정보가 부족함 | 캡처를 확인 필요 상태로 분리한다. | 확인 필요 | **확인 필요 판정 기준** |
| AI-06 | 텍스트가 거의 없는 이미지 | 이미지 분석을 시도하고, 결과가 부족하면 확인 필요로 분리한다. | 정리 완료 또는 확인 필요 | **이미지 분석 가능 범위** |
- 정리 완료 기준
    - 정리 완료 기준은 자동 정리 결과를 바로 사용자에게 보여줄 수 있는지 판단하는 기준이다.
    - 확인 필요 상세에서 사용자가 직접 저장하는 경우에는 컬렉션만 필수이며, 제목과 요약은 비어 있거나 부족해도 저장할 수 있다.
    
    | 항목 | 정리 완료 기준 |
    | --- | --- |
    | 제목 | 사용자가 캡처 내용을 대략 파악할 수 있는 제목이 생성되어야 한다. |
    | 요약 | 캡처의 핵심 내용을 1줄로 이해할 수 있는 요약이 생성되어야 한다. |
    | 컬렉션 | 기본 컬렉션 4개 중 하나로 분류되어야 한다. |
    | 원본 이미지 | 상세 화면에서 확인 가능한 원본 이미지 또는 참조값이 있어야 한다. |
    | 상태 처리 | 위 조건을 충족하면 정리 완료 상태로 저장한다. |
- 확인 필요 기준
    - 확인 필요는 AI 분석은 완료됐지만, 자동 정리 결과를 그대로 정리 완료로 보내기에는 불확실한 상태를 의미한다.
    
    | 확인 필요 사유 | 기준 |
    | --- | --- |
    | 제목 불확실 | 제목이 비어 있거나, `제목 없음`처럼 캡처 내용을 대표하지 못하는 경우 |
    | 요약 불확실 | 요약이 비어 있거나, 핵심 내용을 설명하지 못하는 경우 |
    | 컬렉션 불확실 | 기본 컬렉션 4개 중 어디에 넣을지 명확하지 않은 경우 |
    | 정보 부족 | 이미지 안의 텍스트나 시각 정보가 부족해 의미 있는 정리가 어려운 경우 |
    | 분석 결과 애매함 | AI가 생성한 결과는 있지만 사용 목적을 확정하기 어려운 경우 |
    | 텍스트 없음 | OCR 텍스트가 거의 없고, 이미지 분석만으로도 제목/요약/컬렉션을 충분히 만들기 어려운 경우 |
- 실패 안내와 확인 필요 구분
    - 실패 안내는 정리 결과 자체가 만들어지지 않았거나, 정리 과정이 중단되어 다시 시도해야 하는 상태다.
    - 확인 필요는 사용자가 결과를 확인하고 보정하면 저장할 수 있는 상태다.
    
    | 구분 | 기준 | 처리 |
    | --- | --- | --- |
    | 확인 필요 | 분석은 완료됐지만 결과 품질이 부족한 경우 | 확인 필요 상태로 분리 |
    | 실패 안내 | 업로드 실패, 네트워크 오류, AI 응답 실패, 서버 오류 등으로 분석 자체가 완료되지 않은 경우 | 실패 안내 및 재시도 제공 |
